# 演習課題

研修テキスト（docs/01_training_text.md）の各セクションと対応しています。
時間が余った方向けの発展課題も用意しています。

---

## 演習1: チャンク分割のパラメータを変えてみる（step1関連）

`step1_load_and_chunk.py` を実行し、`chunk_size` と `chunk_overlap` の値を
以下のように変えて、それぞれチャンクの数と中身を観察してください。

| パターン | chunk_size | chunk_overlap |
|---|---|---|
| A（デフォルト） | 400 | 80 |
| B（小さい） | 150 | 30 |
| C（大きい） | 800 | 100 |
| D（オーバーラップなし） | 400 | 0 |

**考えてみましょう:**
- チャンクを小さくしすぎると何が起きそうですか？（文脈が途切れる、検索がノイズに弱くなる等）
- チャンクを大きくしすぎると何が起きそうですか？（余計な情報が混ざる、LLMへの入力コストが増える等）
- オーバーラップが0だと、どんな問題が起きそうですか？

## 演習2: 検索結果の「距離」を観察する（step3関連）

`step3_search.py` で、以下の質問を試し、上位3件の「距離（distance）」の値を記録してください。

1. `"パスワードのルールを教えて"`（社内文書に明確に載っている質問）
2. `"プリンターのインクが切れました"`（文書にやや近い言い回しの質問）
3. `"今日のランチのおすすめは？"`（社内文書と全く関係ない質問）

**考えてみましょう:**
- 3パターンで距離の値はどう違いましたか？
- 「関連している」と判断してよい距離のしきい値はどのくらいだと思いますか？
- しきい値を設けて「しきい値より遠い結果は使わない」ようにすると、RAGの動作はどう変わりそうですか？

---

## 演習3: ハルシネーション（もっともらしい嘘）を観察する（step4関連）

`step4_rag_answer.py` で、社内文書に**書かれていない**質問を試してください。

```
python step4_rag_answer.py "リモートワーク手当は月いくらもらえますか"
python step4_rag_answer.py "オフィスの最寄り駅はどこですか"
```

**考えてみましょう:**
- Claudeは「わかりません」と正直に答えましたか？ それとも、それらしい回答を作ってしまいましたか？
- もし知ったかぶりをしてしまった場合、`SYSTEM_PROMPT`（step4_rag_answer.py内）の
  どの部分を強化すれば改善できそうですか？ 実際に書き換えて試してみましょう。

---

## 演習4: top_k（検索件数）を変えてみる

`step4_rag_answer.py` の `ask()` 関数の `top_k` 引数を 1 / 3 / 5 に変えて、
同じ質問（例:「VPNに接続できません」）を実行し、回答の質やコストの変化を比較してください。

**考えてみましょう:**
- top_k を増やすと、回答の質は上がりましたか？ コスト（トークン数）はどう変わりましたか？
- 「多ければ多いほど良い」わけではない理由を考えてみましょう。

## 発展課題A: 自分たちの文書を追加する

`code/sample_docs/` に、皆さんの部署に関連する架空のFAQやマニュアルを
Markdown形式で1つ追加し、`step2_build_vectorstore.py` を再実行してから
質問してみましょう。実際の業務文書に近いテーマで試すと理解が深まります。

## 発展課題B: 出典を表示する仕組みを改善する

現在の実装では、LLMが「出典」をテキストとして自己申告しています。
より確実な方法として、`step4_rag_answer.py` の `generate_answer()` を改造し、
検索でヒットしたチャンクのファイル名を**コード側で**回答の末尾に
必ず追記するように変更してみましょう（LLMの申告に頼らない方法）。

## 発展課題C: 評価用の質問セットを作る

10問程度の「想定質問と正解（社内文書のどこに書かれているか）」のセットを作成し、
全問についてRAGボットが正しい文書から回答できているかをチェックする
簡単な評価スクリプトを書いてみましょう（RAGの「評価（Evaluation）」の第一歩です）。
